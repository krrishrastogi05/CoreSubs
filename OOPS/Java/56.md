Dynamic Method Dispatch is the exact mechanism by which Java implements Runtime Polymorphism [00:00]. It is the process where a call to an overridden method is resolved dynamically at runtime rather than at compile time.

The Golden Rule: You can create a reference variable of a parent class (superclass) and assign it the object of a child class (subclass) [01:43].

Analogy: Think of a Computer and a Laptop. Since a laptop is a computer, you can point to a laptop and say, "That is a computer." In Java, a Computer reference can hold a Laptop object [02:14].

When you use a parent reference to call a method, the Java compiler only checks if the method exists in the reference type (the parent). It does not know which method will actually execute. The JVM decides the execution strictly at runtime based on the actual object instantiated in the memory [06:51].

Memory Perspective: When a reference variable is reassigned to a new child object, the old link on the Heap memory is broken, and a new link is formed to the new object [04:32]. The method that gets executed is always fetched from the actual object sitting in the Heap memory at that exact moment.

Trick Question 1: "What happens if obj tries to call a method that is ONLY present in Class B, but not in Class A?"
Answer: It will result in a Compile-Time Error. Even though the object is of Class B, the reference type is Class A. The compiler restricts you to only calling methods that are declared in the reference type (Class A).

Trick Question 2: "Can I do A obj = new D(); if D is a completely independent class?"
Answer: Absolutely not. This will not compile. Dynamic Method Dispatch strictly requires an inheritance structure (the IS-A relationship) to work.
