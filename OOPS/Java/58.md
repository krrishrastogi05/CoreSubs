Welcome back to your Java OOPs interview prep! Today, we are tackling a foundational topic that is practically a guaranteed discussion point in L1/L2 interviews at Indian FAANG companies and top startups (like Swiggy, Cred, or Razorpay). 

The topic is the cosmic parent of all Java classes: the **`Object` class**, and its holy trinity of methods: **`toString()`, `equals()`, and `hashCode()`**. 

Here is the deep-dive theoretical analysis, followed by interview-ready code based on the video.


---

### 1. The Supreme `Object` Class (The "Why")
In Java, even if you don't explicitly extend any class, your class secretly inherits from the `java.lang.Object` class [[00:17](http://www.youtube.com/watch?v=dCt9sfZV8Sg&t=17)]. Because of this, every single object you create automatically inherits several built-in methods, such as `toString`, `equals`, `hashCode`, `wait`, and `notify`. 

Let's break down the three most commonly tested ones.

### 2. The `toString()` Method
**What it does:** It provides a string representation of your object. 
**Interview Trap:** Interviewers will ask, *"What happens if you just pass an object to `System.out.println()`?"*
* **The Answer:** Behind the scenes, Java automatically calls the `toString()` method on that object [[02:40](http://www.youtube.com/watch?v=dCt9sfZV8Sg&t=160)]. 
* **Default Behavior:** If you don't override it, the default `Object` class implementation fires. It prints the class name, an `@` symbol, and the hexadecimal version of the object's hash code (e.g., `Laptop@2a139a55`) [[03:16](http://www.youtube.com/watch?v=dCt9sfZV8Sg&t=196)].
* **The Fix:** You must **override** `toString()` in your class to print meaningful business values (like the laptop's model and price) instead of memory-like gibberish.

### 3. The `equals()` Method
**What it does:** It is used to compare two objects to see if they are "equal".
**Interview Trap:** *"Why use `.equals()` instead of the `==` operator?"*
* **Default Behavior:** By default, the `Object` class's `equals()` method does the exact same thing as `==`: it compares the **memory references** of the objects [[07:20](http://www.youtube.com/watch?v=dCt9sfZV8Sg&t=440)]. If two different objects in memory have the exact same data, the default `equals()` will still return `false`.
* **The Fix:** You must **override** the `equals()` method to perform a **Value Comparison** (e.g., "Are the model and price the same?") rather than a Reference Comparison. 

### 4. The `hashCode()` Method & The "Golden Contract"
**What it does:** It applies a hashing algorithm to your object's data to generate a fixed-size integer representation (a hash code) of that object [[04:00](http://www.youtube.com/watch?v=dCt9sfZV8Sg&t=240)].
**The FAANG Favorite Question:** *"What is the contract between `equals()` and `hashCode()`?"*
* **The Golden Rule:** In Java, if two objects are considered equal according to your overridden `equals()` method, they **MUST** return the exact same integer when `hashCode()` is called [[09:49](http://www.youtube.com/watch?v=dCt9sfZV8Sg&t=589)].
* **Why it matters:** If you override `equals()` but forget to override `hashCode()`, your objects will break severely when stored in hash-based data structures like `HashMap` or `HashSet`.

### 💻 Interview-Ready Code Example

Here is how you actually implement this. **Pro-Tip:** In real-world startups and coding rounds, you should never write these by hand! Tell the interviewer you would use your IDE (like IntelliJ/Eclipse) to generate them to avoid null-pointer bugs, or use the `@Data` annotation from the Lombok library [[10:01](http://www.youtube.com/watch?v=dCt9sfZV8Sg&t=601)].

```java
class Laptop {
    String model;
    int price;

    public Laptop(String model, int price) {
        this.model = model;
        this.price = price;
    }

    // 1. Overriding toString() for meaningful printing
    @Override
    public String toString() {
        return "Laptop Model: " + model + " | Price: $" + price;
    }

    // 2. Overriding equals() for logical state comparison
    @Override
    public boolean equals(Object obj) {
        // Step 1: Check if comparing to itself
        if (this == obj) return true;
        
        // Step 2: Check for null and class type mismatch
        if (obj == null || this.getClass() != obj.getClass()) return false;
        
        // Step 3: Downcast and compare actual values
        Laptop that = (Laptop) obj;
        return this.price == that.price && this.model.equals(that.model);
    }

    // 3. Overriding hashCode() to satisfy the Golden Contract
    @Override
    public int hashCode() {
        // Using Java's built-in Objects utility to hash the relevant fields
        return java.util.Objects.hash(model, price);
    }
}

public class Main {
    public static void main(String[] args) {
        Laptop lap1 = new Laptop("MacBook M2", 1200);
        Laptop lap2 = new Laptop("MacBook M2", 1200);

        // toString() implicitly called
        System.out.println(lap1); 
        // Output: Laptop Model: MacBook M2 | Price: $1200
        
        // == compares memory reference (Different objects = false)
        System.out.println(lap1 == lap2); 
        // Output: false
        
        // .equals() compares logical values (Same data = true)
        System.out.println(lap1.equals(lap2)); 
        // Output: true
    }
}
```
